# Review context: Samsung HVAC Local

**What it is.** Local control of Samsung air conditioners (NASA protocol) through a small ESPHome bridge on the
indoor unit's F1/F2 bus: an M5Stack ATOM Lite on the ATOM RS485 base, running this project's open-source ESPHome
packages. The app talks to that bridge only, on the local network. No cloud, no Samsung account, no third-party
service.

**One device per indoor unit.** A bridge can serve several indoor units (multi-split). Devices that share a bridge
share one connection, kept in `app.js` (`getBridge` / `releaseBridge`, reference-counted).

**ESPHome native API, implemented in the app.** `lib/esphome/` is a small client for the ESPHome native API over
TCP port 6053 with the Noise encryption the API requires (`Noise_NNpsk0_25519_ChaChaPoly_SHA256`), using only Node's
built-in `net` and `crypto`. There are no runtime dependencies on purpose (RAM). Incoming bytes are framed and
capped (`MAX_BUFFER`); a receive buffer above the cap closes the connection.

**Discovery.** The `esphomelib` mDNS-SD strategy finds ESPHome nodes; the app keeps only those whose TXT record
`project_name` matches this project's bridge. The bridge's address is followed when mDNS announces a new one, and
stored in the device store so it survives a restart. Manual entry (host and key) is the fallback for networks where
mDNS does not cross VLANs.

**Credentials.** The bridge's API encryption key is entered once at pairing and kept in the device store. It is
never logged.

**Timers.** `lib/esphome/connection.js` has no Homey reference, so its short request and handshake timeouts use
Node's timers; each is cleared when its reply arrives, and all are cleared in `close()`. The reconnect timer lives in
`lib/bridge.js` and uses `this.homey.setTimeout`, with exponential backoff up to a fixed maximum; `stop()` clears it
when the last device using the bridge is removed or the app unloads.

**Store writes.** Small values only and only on change: the bridge address when it moves, the last active mode (to
restore it when the device is switched on), and a capability-revision marker once after an update.

**Capability changes in 0.1.2.** Auto clean moved from `onoff.auto_clean` to the custom `samsung_auto_clean`
and the fault alarm from `alarm_generic` to `alarm_problem`, so every Flow card has its own clear title. Devices
paired with an older version lose the old capabilities once, in `syncCapabilities` (`LEGACY`).

**Filter Flow cards.** For the sub-capability `alarm_generic.filter` Homey generates only the two "for the duration"
cards, no plain trigger or condition (checked in the device's card list on Homey 12.x). The cards `filter_alarm_on`,
`filter_alarm_off` and `filter_needs_cleaning` fill that gap; they are not duplicates.

**Firmware.** Requires Homey 12.4.0 or later.
